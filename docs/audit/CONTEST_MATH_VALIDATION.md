## 1. What is validated

The engine's realized contest is top-K **Plackett–Luce** generated by the Gumbel-max rule
`score_i = log w_i + Gumbel(u_i)` (`core.py` L406–413 pre-repair). The repaired engine must price the
household's expected win probability with the *same* object (contract D2). This module is that object:

* **exact** individual win probabilities by subset dynamic programming (machine precision, `n ≤ 20`);
* a **deterministic** large-n algorithm (Poisson-binomial / exponential-race quadrature) for `auto` path
  (amendment A5: no unseeded RNG, no MC noise on the engine decision path);
* a caller-seeded **Monte-Carlo** path retained only as the independent validation reference;
* `pl_realize(weights, seats, u)` — the exact Gumbel-max draw from caller-supplied uniforms (deterministic,
  policy-invariant RNG per contract §7).

Because the reference module and the engine's realized draw must agree by construction, this validation
establishes (i) the engine's expected probabilities equal its realized sampling probabilities, and (ii) the
numbers the approximation-error study uses as truth are genuinely exact PL probabilities.

## 2. Binding API implemented (contract §1.3 + A5/A6)

```python
pl_win_probs(weights, seats, method='auto'|'exact'|'mc', rng=None, n_mc=20000)
    # auto   : DETERMINISTIC f(weights, seats); exact DP n<=20, quadrature n>20;
    #          renormalised so sum_i P_i == seats (hard-checked, raises on violation)
    # exact  : subset DP, exact to machine precision for n<=12, documented cap 20,
    #          raises ValueError beyond the cap (A6: never silently approximate)
    # mc     : validation-only; requires caller-seeded rng; returns (p, se)
pl_win_probs_detail(...) -> (p, info)   # method, n, seats, seats_eff,
                                        # max_error_estimate, runtime_ms, sum_p,
                                        # n_quadrature_nodes | se
pl_win_probs_exact(weights, seats)      # exact path only
pl_win_probs_mc(weights, seats, rng, n_mc) -> (p, se)
pl_realize(weights, seats, u) -> bool mask
pl_log_weights(weights)
```

`auto`/`exact` are pure functions of `(weights, seats)` — `rng`/`n_mc` are ignored on those paths.
All functions are pure NumPy, import nothing from `eduengine`, and are scale-invariant in the weights.

### 4.3 `auto` = `exact` for 12 < n ≤ 20 (A5 requirement, tolerance 1e-10)

`method='auto'` uses the exact subset DP through n=20 and the deterministic quadrature only above it. Measured
for n ∈ {13,15,18,20} × seats ∈ {1, 2, n/3, n/2, n−2}, dispersion 1.5: **max |auto − exact| = 0.0** (the two
paths are bit-identical by construction). This satisfies both "exact for n≤12" and the stronger
`12<n≤20` equality check in the amendment.

### 4.4 Independent check of the deterministic quadrature itself

Quadrature vs exact subset DP, n = 13,15,18,20 × **all** seats 1..n−1 × log-weight dispersion {0,1,2,4,6}:
**max |diff| = 1.00e-05**, i.e. the deterministic large-n algorithm reproduces the exact truth to the
`t_lo`-truncation level (documented bound 2e-3, conservative by ~200×). The residual is the omitted
lower-tail mass `Σ_i w_i t_lo`, removed by the seat-sum renormalisation in `auto`.

### 4.5 Exact subset DP vs Monte Carlo (independent estimator)

45 cells: n ∈ {2,3,5,8,12} × dispersion {0.25,1.0,2.0} × seats {1,2,n/2,n−1}, `n_mc = 100 000`
(SE ≤ 1.6e-3). **max |exact − mc| = 0.00373**, **max z = |diff|/SE = 2.42** — every cell within 4σ, no
systematic drift. `se = sqrt(p(1−p)/n_mc)` (exact binomial marginal SE of a multinomial win indicator;

## 6. Limits and caveats

1. **Exact cap.** The subset DP is `O(n 2^n)`; beyond n=20 it raises by design (A6). It is used by `auto` only
   for n≤20 — small contests, where it costs 0.1–0.3 s at n=20 (a one-off per gate-year, not per child).
2. **Quadrature accuracy.** Documented bound 2e-3 (truncation `t_lo=1e-5`, tail `exp(−14)`, Simpson h=0.1 in
   log t); measured 1e-5 vs exact at n≤20 and ≤2.0e-3 vs 400k MC at n=300/400.
3. **Node cap.** The t-grid is capped at 1600 Simpson nodes. Relative weights spanning more than ~e^70 beyond
   the maximum are floored at `1e-30 × max` (their win probability is <1e-28, far below the error bound); this
   keeps all intermediates finite for arbitrary positive weights. The 2e-3 bound is stated for the contract grid
   (log-weight dispersion ≤ 6).
4. **MC reference.** All MC numbers are seeded and reproducible; SE is the exact binomial marginal SE. Host was
   a 2026 M-series Mac, NumPy 2.2.6, Python 3.10.2; runtimes are single-call wall clock and may differ on the box.
5. **No box was used.** Per the Commander's quota correction the validation grid ran locally on the host
   (single-threaded BLAS, no process pool); there is no oversubscription caveat to record and no legacy
   directory was touched.
6. **Scope.** This validates the probability module only; it makes no claim about engine values(), the
   realized admission series, or calibration — those are engine-core/engine-tutoring deliverables.
