# 01 · Run and rebuild the Atlas

**Goal.** Take the delivered folder, install what it needs, run every check, rebuild the single-file app, and know
what `RUN_REPORT.md` is telling you. This is the first recipe: everything else assumes it works.

**You need.** The project folder (a zip is fine, no git required), Python 3.10 or newer (3.11 is what the checked
run used; CI uses 3.12), and Node if you want the browser checks (Node 18 and 26 both work here; CI uses 22).
Internet is needed only for `pip install` and the public-data download.

## Steps

1. **Open a terminal in the project root** (the folder containing `START_HERE.md` and `run_all.py`) and check the
   interpreter:

   ```bash
   python3 --version     # 3.10 or newer
   node --version        # optional; v18+ is enough
   ```

2. **Make a virtual environment** and install the requirements. On macOS/Linux:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

   `requirements.txt` contains numpy, scipy, matplotlib and pandas. Activate the environment in every new shell
   (`source .venv/bin/activate`); if a command fails with `ModuleNotFoundError`, this is the first thing to check.

3. **Run the quick suite.**

   ```bash
   python run_all.py
   ```

   It prints one line per step — `PASS  <step>  (<seconds>s)` or `FAIL` — writes `RUN_REPORT.md`, regenerates
   `web/data/atlas_data.js`, and rebuilds `index.html`. Exit code 0 means every step passed. Expect about a minute
   or two on a laptop: the checked run of 6 November 2026 (19 steps) recorded roughly 95 seconds of step time, the
   round-8 tests taking about 30 seconds and the child-labour/Cambodia checks 14–18 seconds each. `START_HERE.md`'s
   "about 10 seconds" is out of date. If Node is absent, the seven Node-gated steps are skipped with one note in the
   report; the rest still run.

4. **Read `RUN_REPORT.md`.** Two sections matter:

   - The step table: every test, export and build, with `pass`/`FAIL`, seconds, and the last lines of output. One
     `FAIL` means the tree is not self-consistent; scroll up in the terminal for the failing step's last 25 lines.
   - "Headline results (stored)": the China fit, Tilly mechanisms, strict forecasts, demand inversion and so on.
     The quick run does **not** refit. These numbers are read from `engine/firms/results/*.json`; they move only
     when a fit is re-run (step 5), not when you merely rebuild the app.

   The report labels fit statistics and tests, following `docs/facts_register.md`: a number the parameters were
   fitted to is not evidence. "All pass" means the tests and stored artifacts agree with the code, not that the
   assumptions are true.

5. **Refit everything only when asked.** `--full` adds the long China and Tilly fits, the cross-country Monte Carlos,
   the Cambodia calibration ridge and the story tournament (the step names in `run_all.py` say which):

   ```bash
   python run_all.py --full     # 1-2 hours; leave it running
   ```

   It rewrites the stored results under `engine/firms/results/` and `engine/results/`, then updates the report.
   Do this after a data change (recipe 02), not before. To see the stored headline numbers without running anything:

   ```bash
   python run_all.py --report   # prints the stored headline results (and rewrites RUN_REPORT.md)
   ```

6. **Rebuild the app from source.** Never edit `index.html` by hand. Edit `web/*.js` or `web/style.css`, then:

   ```bash
   python build_web.py
   ```

   Expected output is one line: `wrote index.html <N> KB`. The script inlines the stylesheet, `web/data/atlas_data.js`
   (generated by `engine/firms/export_web.py`, which `run_all.py` calls) and the scripts listed in `build_web.py`
   into `web/index.src.html`. `run_all.py` already does this as its "Build index.html" step.

7. **View it.** Open `index.html` in any browser — double-click it, or `open index.html` on macOS. It is one
   self-contained file: no server and no account. The only network request is the optional Google Fonts stylesheet
   imported by `web/style.css`; the font stack has system fallbacks, so it also works offline. Choose a world, move
   a lever, and check the page renders; the app's source is `web/app.js`.

8. **Run a single check while you work.** These are the same steps `run_all.py` runs, and are much faster than the
   whole suite:

   | What | Command | Run from |
   |---|---|---|
   | China firm tests (31) | `python -m unittest firms.test_firms firms.test_tilly` | `engine/` |
   | Monte Carlo manager tests (15) | `python -m unittest test_mc` | `engine/` |
   | Cross-country and story-hook tests (5) | `python -m unittest test_childworld` | `engine/` |
   | Checked-input tests (11) | `python tests/test_evidence.py` | project root |
   | Browser model vs Python | `node tests/js_parity.mjs` | project root |
   | Planning Lab tests (30) | `node tests/test_lab.cjs` | project root |
   | Child-labour simulator tests (21) | `node tests/test_childlabour.cjs` | project root |
   | Cambodia world tests (26) | `node tests/test_camchild.cjs` | project root |
   | Cambodia Python twin vs browser | `python tests/camchild_parity.py` | project root |
   | Round-8 conclusions (14) | `python tests/test_round8.py` | project root |
   | Planning kernel | `node planning/test_kernel.cjs` | project root |

   `node tests/js_parity.mjs` compares `web/youth.js` with Python reference runs stored in `web/data/atlas_data.js`.
   If it fails after you edited a model, re-export first: `cd engine && python -m firms.export_web`, then run the
   parity test from the project root.

## Checks

- `python run_all.py` exits 0 and every step in `RUN_REPORT.md` says `pass`.
- The report's "Headline results (stored)" section is present and labels fit statistics versus tests.
- `python build_web.py` prints one line, and the rebuilt `index.html` opens and runs a world.
- After a rebuild the tracked outputs are unchanged: `git diff --exit-code -- index.html web/data` (in a git
  checkout), or the same files have the same hashes before and after in a plain zip copy.

## The CI parity rule

`.github/workflows/ci.yml` runs `python run_all.py` on Python 3.12 and Node 22 for every push and pull request, then
runs:

```bash
git diff --exit-code -- index.html web/data
```

So a build that changes `index.html` or `web/data/` fails CI unless the rebuilt files are committed in the same
change. The rule in practice: edit `web/` sources, rebuild with `python build_web.py` (or `run_all.py`), and treat
both the source change and the rebuilt `index.html` / `web/data/` as part of the change. `RUN_REPORT.md` is listed
in `.gitignore` and is not part of that check.

## Common failures

- **`ModuleNotFoundError: numpy` / `scipy` / `matplotlib` / `pandas`.** The virtual environment is not active, or
  the requirements were installed into a different Python. Activate it and re-run `pip install -r requirements.txt`;
  check with `python -c "import numpy, scipy, matplotlib, pandas"`.
- **Matplotlib warns that its cache directory is not writable.** Seen on this machine:
  `.../.matplotlib is not a writable directory` followed by a fallback to a temp directory. It does not fail the
  run. To silence it and speed up repeated imports, point the cache at a writable place:
  `export MPLCONFIGDIR="$HOME/.cache/matplotlib"`.
- **The public-data download fails with `ModuleNotFoundError: requests`.** `download_public_data.py` needs
  `requests`; it was added to `requirements.txt` in the 6 November 2026 run, so a fresh `pip install -r
  requirements.txt` covers it. If you had installed before that, run `pip install requests`. See recipe 06, item B4.
- **The run fails at "Export data for the browser".** `engine/firms/export_web.py` reads
  `engine/firms/results/china_fit.json`, `tilly_fit.json` and `tilly.json`. If those were deleted, restore them or
  run `python run_all.py --full` (1–2 hours) to regenerate them.
- **`node: command not found`.** `run_all.py` detects Node with `shutil.which('node')` and skips the browser steps
  with a note. Install Node LTS (CI uses 22) if you need them, or run only the Python tests.
- **`js_parity` fails after a model edit.** Either the browser mirror and the Python model disagree (fix both — the
  rule is in `START_HERE.md`) or `web/data/atlas_data.js` is stale. Re-run
  `cd engine && python -m firms.export_web`, then the parity test.
- **`index.html` changed by hand and CI fails.** Rebuild from `web/` sources; do not commit hand edits to generated
  files. The same applies to `web/data/atlas_data.js` and `web/data/camchild_runs.js`.
