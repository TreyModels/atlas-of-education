# How I verified the AI-assisted work

Appendix note for the methods paper. Atlas of Education v0.11, 6 November 2026. Every claim below names the file or test that carries it. The note is deliberately about verification, not about results: passing a test here means the code does what it says, not that the theory is true.

**What this note describes.** The repository as of the full refit of 6 November 2026 (the shipped `RUN_REPORT.md`): **every run step passes** — the quick suite (115 Python unit tests across eight suites, the round-8 stored-and-rerun tests, the Node suites: 30 Planning Lab tests, 26 Cambodia child-labour tests, 21 child-labour-simulator tests, browser–Python parity, the Python–browser Cambodia twin, the planning-kernel checks) plus the 1–2 hour refit steps. The input-verification pass of the same day replaced the last from-memory China values and corrected one adjacent error; `tests/test_evidence.py` was re-synced in the same change (13 tests, including "no `m` flag remains"), so the shipped report and the tests now describe the same data. That episode is itself the example of the tripwire working — the tests guard input provenance and failed the moment the input moved — and is worth telling in the appendix as such.

## 2. How the AI-assisted work was cross-checked

1. **Second-agent audit of the supplied input audit.** A separate agent produced `docs/input_audit_supplied.md` (107 memory-flagged entries reviewed, 106 proposed to become `v`, 1 drop, 2 value corrections). The main lane then checked it against sources and applied only what was right: `docs/UPDATE_2026_11_05.md` records "the supplied audit was checked independently against sources… two of its corrections were wrong and were not applied", and keeps the pre-fix results in `engine/firms/results/before_input_fix/` so the change is auditable. The supplied audit itself says "audit only… has not been edited" — that status is correct and the application history exists only in the later docs.
2. **Page fetches, logged.** The China inputs were checked against fetched pages rather than memory: MoE communiqués for tertiary entrants, the MoE 2022 bulletin component sum, the NBS yearbook 2011 birth-rate table, and NBS monthly releases as reported by Xinhua, China Daily, Yicai and Global Times. Sources live in `SOURCES` in `engine/firms/data_china.py` and in the tables of `docs/input_audit_supplied.md` and `docs/CHANGES_evidence_lane_2026_11_05.md`; a fetched page that failed (e.g. the NBS monthly release pages returning redirects) is recorded as failed rather than replaced by a guess.
3. **Second implementation.** Every model with two implementations is checked against its twin (`tests/js_parity.mjs`, `tests/camchild_parity.py`); the Cambodia world's Python port was written specifically so the model could be fitted and profiled by code that cannot hide behind the JavaScript.
4. **Independent re-derivation.** Arithmetic checks are tests, not edits: component sums, relative-wage arithmetic, birth reconstruction, and the demand-information perturbation are all recomputed (see the table above). The `_URB_CHECKED` block makes import fail if a "verified" value ever stops matching its checked value.
5. **Deliberate negative controls.** The leak test has a companion test that *should* move the residuals; the "catches a bad edit" layer of `test_round8.py` re-reads stored results as well as re-running the model; the reduced rerun asserts conclusions that survive noise, not decimals.
6. **Facts register before headline claims.** `docs/facts_register.md`, written by reading the code rather than the docs, labels every fact *calibration / test / diagnostic / input* and every mechanism *built in / emergent / tuned*. Rule 2 of that file says a headline number must say whether it is a fit statistic or a test; the run report now labels the 1.27 fit statistic as such.
7. **Protocols recorded before the search.** `engine/tune_protocol.json` records the Atlas engine's training period, seeds, design, acceptance rule and loss before the search; `engine/test_validation.py` enforces that test rows and unverified rows cannot enter selection. The China strict protocols are described in the result files and their leak checks are tested.
8. **The failures kept.** `TODO.md` §"Known failures to keep visible" lists them; `docs/facts_register.md`, `docs/asia_school_work.md` and `engine/firms/results/stories_strict.md` keep superseded claims visible (the withdrawn Kyrgyz pass, the changed India explanation, the "fit statistic" relabelling) instead of deleting them.

## 3. What was not checked, or is only fitted / diagnostic

- **No causal identification anywhere.** The models are calibrated/assumed behavioural structures, not IV, DiD or RCT estimates. Nothing in this repository identifies a causal effect of a real policy. The tests check implementation and bookkeeping, not external validity.
- **China.** The whole-record error 1.27 is a **fit statistic**, not evidence; under the strict protocol the same model scores 5.5–5.8. Tilly's hoarding share (40%), wage wedge (20%) and insider split (50%) are **set, not estimated**. The demand index is backed out of adult unemployment (the youth leak is closed in the strict scripts, but input dependence remains). The tournament winner has **2 of 16 parameters at bounds** and a flat valley not yet profiled — the structure is not rejected, only unproven. Postings (model +2% vs observed −22%) are **not reproduced**. Every China input is now verified or derived: the A1 lane of 6 November removed the last `m` flags (births are `d`), so the flags should be read from the current file.
- **Cambodia.** The child-labour **level is not calibrated**: 13.9–14.4% against 10.7% in the 2012 survey. Protection magnitudes are **placeholders for Bjørn**. The UIS-vs-census observation equation (17.6% vs ~8.4%) is unresolved. The partial-ban increase and Basu–Van hysteresis are **not reproduced**. The 30-seed bands are simulation noise under declared inputs, not parameter or structural uncertainty.
- **Cross-country childworld.** India is a **clean failure** (31% [8–68] school-and-work predicted vs 0.4% observed); the first-round Kyrgyz "pass" is **withdrawn**; state D is not split into care/marriage/disability/idleness; the ABC tolerance and the age-aligned spec-2 tolerance (3×) are chosen, and the resulting composition range is 87 points wide — a weak pass.
- **Relational floor and floorworld.** Stylised household models, wide priors; "accepted draws" are not estimated posteriors; the decisive test (FIES/APIS exit composition) has **not been run**. floorworld is an aggregate toy; its output block is too crude to interpret.
- **Angkor.** Explicitly an **uncalibrated toy**; it fails its historical benchmark on purpose (0/100 reference runs have the Angkor court leading in 1200; median 1500 population ~2.144m). Its seed bands are not parameter or structural uncertainty, and it is not integrated into the Atlas app.
- **China forecast protocol.** The strict Dec 2022/Dec 2024 tests are **not blind**: the test-period errors and the mechanism sets had been seen. Only the Oct–Dec 2026 forecast (`blind_forecast_2026_11.md`) is blind, and it is **pending**. The naive benchmark is defined in the strict scripts; changing it would change the verdict, so the definition is part of the protocol.
- **Uncertainty machinery.** `mc.py` is validated on known answers, but the China "90% confidence region" in `stories.py` is a hand-chosen region, not a posterior; Sobol indices for childworld are computed over priors, not estimated distributions; simulation bands are never reported as confidence intervals.
- **Scope of the suite.** The default `run_all.py` does not re-run the long refits (that is `--full`, 1–2 hours), the massabm/triad rounds other than round 8, or `graduate_supply_test.py`; `engine/tests.py` (22 checks) is available but not wired in. The massification code is exercised only through the round-8 experiments. Kimi's `reference/education_worlds_react_v0.6/` is not run at all. No UI, accessibility, or cross-platform tests exist; the JavaScript tests require Node and are skipped (marked pass) if Node is absent.
- **Environment and reproduction.** The published report was produced on one macOS machine with Python 3.11.17; CI pins Python 3.12/Node 22 but its first run has not happened (no git remote in this copy). Figures are regenerated by scripts but not checked against stored images. No formal statistical inference is used for the test suite: tests assert identities, directions, and exact known answers, not significance levels.
- **Licences and provenance of third-party data** are only partly resolved: see `LICENSES.md` — six of the twelve bundled CSVs are boundary cases, and that is a legal/provenance gap, not a computational one.

## 4. A reviewer's repeatable protocol

1. `pip install -r requirements.txt` in a clean environment; install Node 22. Do not skip the Node tests: they are half the cross-implementation evidence.
2. `python run_all.py` (about 1–2 minutes; the 09:46 report: 19 steps). Read `RUN_REPORT.md`; every step must say pass. If a step fails, stop and report — do not proceed to the numbers.
3. Re-run the suites directly and read the test docstrings: `cd engine && python -m unittest firms.test_firms firms.test_tilly test_validation test_planning test_childworld test_mc test_floorworld`; from the root, `python tests/test_evidence.py`, `python tests/test_round8.py`, `node tests/test_lab.cjs`, `node tests/test_camchild.cjs`, `node tests/test_childlabour.cjs`, `node tests/js_parity.mjs`, `python tests/camchild_parity.py`, `node planning/test_kernel.cjs`.
4. Test the protocol itself, from `engine/`: `python -c "from firms import forecast_strict as F, stories_strict as SS; print(F.demand_leak_check(), SS.leak_check())"` must print `0.0 0.0`; then read the companion non-vacuous test in `firms/test_firms.py` to see that zero is not vacuous.
5. Read `docs/facts_register.md` and, for every headline number you intend to quote, find its role (calibration, test, diagnostic, input). Quote the role with the number. In particular, do not quote the 1.27 whole-record error as evidence.
6. Check the blind forecast when NBS releases Oct–Dec 2026: `cd engine && python -m firms.blind_forecast --score` — and **do not refit first**. The frozen values and the instruction are in `firms/results/blind_forecast_2026_11.md`.
7. Reproduce one stored ensemble from scratch: `cd worlds/angkor/reference/monte_carlo_lab && python monte_carlo.py --seeds 100` (about 21 s per the merge note) and compare `results.json` and `ensemble_100_seeds.csv` with the stored files; or run `python tests/test_round8.py`, which re-runs the reduced round-8 experiments (~30 s) and checks the stored full-size results.
8. Spot-check the inputs: pick three China values, follow their `SOURCES` in `engine/firms/data_china.py` to the fetched pages; re-derive the 2022 tertiary-entrant sum and the relative starting-wage arithmetic; check that `docs/input_audit_supplied.md` still says what was applied where (the audit is a document; the application history is in `docs/UPDATE_2026_11_05.md`).
9. Read `TODO.md` §"Known failures to keep visible" and confirm each failure still appears in the current result files. A failure that has been quietly removed is a red flag larger than a failing test.
10. Verify the build is frozen: `python run_all.py` then `git diff --exit-code -- index.html web/data` (the same check as CI). If it differs, the shipped app is not the build of the sources you read.
11. For anything in the book or paper that quotes a model result, ask two questions: *was it tuned to this?* (if yes, it is a fit statistic) and *would a wrong model also produce it?* (if yes, it is not a test). The repository's own register applies the same questions; the appendix exists to make that audit cheap.

## 5. What a reviewer should conclude, and should not

**Should:** the bookkeeping, the theorem limit cases, the two-implementation parity, the known-answer tests of the uncertainty manager, the information-set leak tests, and the stored-result reproduction are all genuine and runnable from the repository. The reported failures are real and reported. The protocol for scoring is written down before the score where the record allows it.

**Should not:** conclude that the models are empirically validated, that the forecasts are good, that the Cambodian policies have estimated effect sizes, that the Angkor world is calibrated, or that any number in the app is causal. Passing 92 Python unit tests is evidence of engineering and diligence; it is not evidence for a theory of education. The one test that would settle the strongest claim — the relational floor's composition prediction on household data, the blind China forecast, or a profiled valley that forecasts better than naive — is either pending or unrun, and this appendix says so.
