# Contributing a model challenge or repair

Counterexamples and failed explanations are welcome. Start with the purpose and a specific claim in a named model. A contribution can improve a toy explanation while preserving its small scope.

In an issue, include the source commit, run plan or complete settings, observed output, proposition being tested, and proposed explanation or repair. Connect literature to the specific rule it supports, including a page, equation or table. Identify coefficients and institutions that remain assumptions.

For a code repair, add a small known-answer or invariant check. A substantive mechanism change also needs a separate experiment. Preserve the predecessor as a reproducible setting when possible. Pair nuisance settings and exogenous events across the comparison. Report unsuccessful fits, unfinished solvers and counterexamples.

Changing a denominator, sample, functional form, action order, institution or equilibrium selection rule can change the scientific question. Explain the change in the model description and protocol. Shared code supports controlled comparisons; independent implementations can expose errors. Neither supplies independent empirical evidence.

Changes made after seeing an outcome belong in an exploratory amendment. Create a new plan when code or inputs change. Preserve historical outputs under version labels. A society-specific causal or policy claim requires an explicit evaluation argument and suitable outside evidence.

See [the research workbench](research/README.md) for sources, protocols and evidence gaps.
